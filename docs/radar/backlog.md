# 雷達模組・未排期清單

三期完成後可以考慮的項目。每一項都寫了「什麼時候值得做」，沒達到條件前不建議動工。

| #   | 項目               | 什麼時候值得做                                 | 工作量     |
| --- | ------------------ | ---------------------------------------------- | ---------- |
| 1   | 週榜歷史封存       | 第一期穩定運作超過一個月，想回顧過去的榜單     | 小         |
| 2   | 月榜               | 覺得週榜變動太快、想看長期趨勢                 | 小         |
| 3   | 開放搜尋引擎索引   | 第三期上線、已有數篇關聯文章                   | 小         |
| 4   | 同步失敗通知       | 曾經好幾天沒發現同步失敗                       | 小         |
| 5   | PyPI 下載量        | 資安榜的 Python 套件排序不理想                 | 小         |
| 6   | 依賴漏洞比對       | 第二期上線後，想知道「這個漏洞影響我的專案嗎」 | 中         |
| 7   | 刷星異常偵測       | 每週都要手動隱藏好幾個刷星 repo                | 中         |
| 8   | AI 功能重新評估    | 累積的收藏太多、看不完，或真的需要中文摘要     | 中～大     |
| 9   | 新主題（例如股票） | 有明確需求時                                   | 視主題而定 |

---

## 1. 週榜歷史封存

- 每週一凌晨把上週各分類的 Top 10 寫進 `radar_weekly_archives`（模組、ISO 週次、分類、名次、項目快照）
- 前台新增 `/radar/github/2026-w47` 這類網址，列表頁可切換週次
- 快照已經存了，封存只是多寫一張小表

## 2. 月榜

- 把 RPC 的統計天數改成參數（7 天／30 天）；快照本來就保留 35 天，不需要改資料表
- 前台加一個「本週／本月」切換

## 3. 開放搜尋引擎索引

- 拿掉雷達頁的 `noindex`，加進 sitemap 與 `llms.txt`
- 只在雷達頁有自己的內容（關聯文章、說明文字）時才有意義，否則容易被判定為自動產生的低價值頁面

## 4. 同步失敗通知

- 同步失敗或超過 36 小時沒有成功時，發送 Discord／Slack Webhook，或用 Resend 寄信
- 需要新增一個 Webhook URL 或寄信服務的環境變數

## 5. PyPI 下載量

- 用 pypistats.org 的 API 補上 Python 套件的下載量，讓資安榜的排序更完整
- 該 API 有速率限制，需要快取並只查前幾名

## 6. 依賴漏洞比對（取代原本的 Release 追蹤器）

- 讀取本專案的 `pnpm-lock.yaml`，取得實際安裝的套件與版本
- 呼叫 OSV.dev 的 `querybatch` API 批次比對
- 後台雷達總覽顯示「影響本專案的漏洞」與建議升級版本
- 和 Dependabot 的差別：結果集中在自己的後台，並能和資安榜交叉比對

## 7. 刷星異常偵測

- 計算「star 增量 ÷ fork 增量」、「star 增量 ÷ issue／PR 活動」等比值，異常時在後台標示「疑似刷星」
- 精確判斷需要查 stargazers 帳號的建立時間，API 用量很大，先用比值初篩

## 8. AI 功能重新評估

若日後決定加回 AI，需遵守規劃時討論過的原則：

- 只在後台手動觸發，訪客無法呼叫
- 輸出一律先存成草稿，人工審核後才公開
- 只把抓到的官方資料餵給模型，並要求只能依據這些資料回答；用結構化輸出搭配 zod 驗證
- 讀者看得到「AI 整理，以官方公告為準」與原始連結
- 外部內容（README、漏洞描述）視為不可信資料：渲染時沿用 `sanitize-html`，移除不在原始資料裡的連結
- 快取鍵包含「項目 × 分析類型 × prompt 版本」，並記錄模型、token 用量與成本
- API key 只放在 server 端，並在供應商後台設定每月預算上限

適合的用途：收藏筆記的中文摘要、文章編輯器的 SEO／GEO／TL;DR 一鍵補齊（可沿用現有的 `seo-check`、`geo-check` 規則驗證輸出）。

## 9. 新主題（例如股票）

- 架構已支援：新增一個模組 key、一支同步函式、一個 RPC 與前後台頁面即可
- 股票類內容若公開，可能被視為投資建議，建議維持 `hidden`，只給自己看
